=== 0. 手算：两个小集合、三个随机排列 ===
  A = ['a', 'b', 'c', 'd'], B = ['b', 'c', 'd', 'e', 'f']；交 ['b', 'c', 'd']（3 个），并 ['a', 'b', 'c', 'd', 'e', 'f']（6 个）→ Jaccard = 3/6 = 0.500
  排列 1: c < a < e < b < f < d   A 里排最前的 c，B 里排最前的 c → 相等
  排列 2: e < d < a < c < b < f   A 里排最前的 d，B 里排最前的 e → 不等
  排列 3: b < f < c < a < d < e   A 里排最前的 b，B 里排最前的 b → 相等
  3 个签名里 2 个相等 → 估计 Jaccard ≈ 2/3 = 0.667（真实 0.5；签名越多越准）
  为什么相等的概率恰好是 Jaccard：并集 6 个元素里谁排最前是等可能的；只有当它落在交集（3 个）里，A 与 B 的最小值才相同 → 3/6

=== 3. 2000 段文本（含 300 组近重复）：暴力两两比较 vs LSH 分桶 ===
  两两比较要算 1,999,000 对 Jaccard；LSH 只产生 267 个候选对（0.01%），再对候选精确算
  300 组真实近重复的 Jaccard 分布: 最小 0.64 / 中位 0.81 / 最大 0.96
  Jaccard ≥ 0.7 的真实对 254 个，其中 LSH 找到 226；候选里 Jaccard ≥ 0.7 的共 236（多出来的是碰巧相似的随机对）
  漏掉的都是 Jaccard 低于阈值的：改了 5–6 个词的对 J≈0.6，按 S 曲线只有约 21% 概率成候选——阈值就是这么定的

=== 4. 三层去重：精确 hash、MinHash、embedding——对同一批句子各能抓到什么 ===
  6 句模板文本（换了数字）：精确相同 0 对；字符 5-gram Jaccard 均值 0.70（最小 0.67）；减均值余弦 均值 1.00
  12 句体育（意思相关、措辞不同）：精确相同 0 对；字符 5-gram Jaccard 均值 0.00（最小 0.00）；减均值余弦 均值 0.46
  模板 vs 体育 的减均值余弦均值 -0.20（作对照）
  精确 hash 只抓逐字相同；MinHash 抓改了几个字的模板页（Jaccard 高）；意思相同但措辞不同的句子 Jaccard 低、只有 embedding 相似度能抓——语义去重（SemDeDup）就是在 embedding 上聚类再在簇内按余弦去重
