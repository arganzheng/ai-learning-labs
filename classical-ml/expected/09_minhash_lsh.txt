=== 0. 手算：两个小集合、三个随机排列 ===
  A = ['a', 'b', 'c', 'd'], B = ['b', 'c', 'd', 'e', 'f']；交 ['b', 'c', 'd']（3 个），并 ['a', 'b', 'c', 'd', 'e', 'f']（6 个）→ Jaccard = 3/6 = 0.500
  排列 1: c < a < e < b < f < d   A 里排最前的 c，B 里排最前的 c → 相等
  排列 2: e < d < a < c < b < f   A 里排最前的 d，B 里排最前的 e → 不等
  排列 3: b < f < c < a < d < e   A 里排最前的 b，B 里排最前的 b → 相等
  3 个签名里 2 个相等 → 估计 Jaccard ≈ 2/3 = 0.667（真实 0.5；签名越多越准）
  为什么相等的概率恰好是 Jaccard：并集 6 个元素里谁排最前是等可能的；只有当它落在交集（3 个）里，A 与 B 的最小值才相同 → 3/6

=== 4. 三层去重：精确 hash、MinHash、embedding——对同一批句子各能抓到什么 ===
  6 句模板文本（换了数字）：精确相同 0 对；字符 5-gram Jaccard 均值 0.70（最小 0.67）；减均值余弦 均值 1.00
  12 句体育（意思相关、措辞不同）：精确相同 0 对；字符 5-gram Jaccard 均值 0.00（最小 0.00）；减均值余弦 均值 0.46
  模板 vs 体育 的减均值余弦均值 -0.20（作对照）
  精确 hash 只抓逐字相同；MinHash 抓改了几个字的模板页（Jaccard 高）；意思相同但措辞不同的句子 Jaccard 低、只有 embedding 相似度能抓——语义去重（SemDeDup）就是在 embedding 上聚类再在簇内按余弦去重


=== 5. 可跟踪的小例子：6 段文本、词级 2-gram、k = 6 个随机排列分 b = 3 组 × r = 2，阈值 0.7 ===
  d0: "the cat sat on the mat by the door" → 8 个 shingle
  d1: "the cat sat on the mat by the window" → 8 个 shingle
  d2: "a cat sat on the mat by the window today" → 9 个 shingle
  d3: "machine learning models need lots of data" → 6 个 shingle
  d4: "machine learning models need lots of good data" → 7 个 shingle
  d5: "the quick brown fox jumps over the lazy dog" → 8 个 shingle
  全集 27 个不同 shingle；d0 ∩ d1 = ['by the', 'cat sat', 'mat by', 'on the', 'sat on', 'the cat', 'the mat']
  d0 ∪ d1 多出来的：['the door', 'the window']
  精确 Jaccard（只列有交集的对）：(d0,d1) 0.778，(d0,d2) 0.545，(d1,d2) 0.700，(d3,d4) 0.625
  签名矩阵（seed=9；每列一个排列，值 = 排列后集合里最小的位置；竖线分 band）：
    d0:  2  2 |  8  5 |  0  4
    d1:  0  2 |  5  3 |  0  4
    d2:  0  0 |  3  2 |  0  2
    d3:  7  3 |  0  0 |  4  3
    d4:  7  1 |  2  0 |  4  1
    d5:  3  8 |  1  1 |  1  0
  候选对（某个 band 的 2 个签名全等）与精确复核：
    (d0, d1)：band [2] 全等，签名相等 3/6，精确 Jaccard 0.778，J ≥ 0.7 → 判重复
  真实 Jaccard ≥ 0.5 却没进候选的对：
    (d0, d2)：Jaccard 0.545，签名相等 1/6，但 3 个 band [0, 1, 2] 各自至少有一列不等——没有一个 band 完整命中，理论上这对成候选的概率只有 1 − (1 − 0.545²)³ = 0.653
    (d1, d2)：Jaccard 0.700，签名相等 2/6，但 3 个 band [0, 1, 2] 各自至少有一列不等——没有一个 band 完整命中，理论上这对成候选的概率只有 1 − (1 − 0.700²)³ = 0.867
    (d3, d4)：Jaccard 0.625，签名相等 3/6，但 3 个 band [0, 1, 2] 各自至少有一列不等——没有一个 band 完整命中，理论上这对成候选的概率只有 1 − (1 − 0.625²)³ = 0.774
  漏掉不是 bug：候选阶段按概率命中，S 曲线在阈值附近本来就是一半一半；精确复核只能救候选里的假阳，救不了没进候选的对

  独立随机排列下，签名相等率 = Jaccard、候选概率 = 1 − (1 − J^r)^b 都是精确的期望；(a·x + b) mod p 这种仿射 hash 只是近似，这里与理论差在千分位；把 a 固定为 1 让 k 个 hash 高度相关，候选概率就塌回接近 J 本身——公式的前提是各列独立，hash 族不满足就不能照搬

=== 5c. 近重复不传递：d0 ≈ d1、d1 ≈ d2、d0 ≉ d2，保留谁 ===
  阈值 0.7 下判为重复的对：[(0, 1), (1, 2)]；(d0, d2) 的 Jaccard 0.545 不够——重复关系不传递
  策略 A 连通分量（并查集）：分量 [[0, 1, 2], [3], [4], [5]]，每个分量留编号最小的 → 保留 [0, 3, 4, 5]，d2 被删，虽然它和代表 d0 的 Jaccard 只有 0.545
  策略 B 贪心按顺序 [0, 1, 2, 3, 4, 5]：保留 [0, 2, 3, 4, 5]（只与已保留的代表比，删除的都与某个代表 J ≥ 0.7）
  策略 B 贪心按顺序 [1, 0, 2, 3, 4, 5]：保留 [1, 3, 4, 5]（只与已保留的代表比，删除的都与某个代表 J ≥ 0.7）
  策略 B 贪心按顺序 [2, 1, 0, 3, 4, 5]：保留 [0, 2, 3, 4, 5]（只与已保留的代表比，删除的都与某个代表 J ≥ 0.7）
  连通分量删得多、保留集互不相似但可能删掉与代表并不相似的文本；贪心保留的每一条都离代表够远但结果依赖扫描顺序。两种都对，选哪种取决于你更怕漏删（训练集重复）还是误删（丢内容）——先定策略再谈去重率
  700 段（500 随机 + 100 条两步改写链）：J ≥ 0.7 的对 239，连通分量里 J < 0.7 的同组对 93 个（不传递的证据）
  连通分量保留 500 段；贪心正序保留 564 段、倒序保留 566 段——同一批重复对，三种答案
