=== 漏斗：从网页到训练 token（公开数据集的刻度）===
           约 30+ PB 压缩                Common Crawl 全部快照的原始网页（WARC）
   100.0%  240T token                 抽出正文后的文本（DCLM-Pool，2023 前全部快照）
     6.2%  15T token，44 TB parquet    URL / 语言 / 启发式过滤 + 去重后（FineWeb，96 个快照）
     2.2%  5.4T token                 再按'教育价值'分类器打分 >= 2（FineWeb-Edu）
     0.5%  1.3T token                 分类器打分 >= 3（FineWeb-Edu 高分子集）
     1.6%  3.8T token                 DCLM-baseline：启发式 + 去重 + fastText 取前 10%
  15T 的通用网页语料是抽出正文后文本的 6%；模型打分后的'高质量'子集只剩 0.5%–1.6%。

=== 管线的 CPU 账（15T token 的最终语料，假设见源码顶部）===
  正文抽取（所有抓取页）                   694,444 核·小时 =   28.9 天 @ 1000 核
  MinHash 签名（去重前文本）               7,000 核·小时 =    0.3 天 @ 1000 核
  tokenize（最终语料）                 16,667 核·小时 =    0.7 天 @ 1000 核
  对照：Llama-3 8B 的训练是 146 万 GPU 小时；数据管线的成本以 CPU 核·小时计、贵在正文抽取与去重，不在 tokenize。

=== 存储与训练时的读取带宽 ===
  15T token 的 id（uint32）          60 TB   （FineWeb 的文本 parquet 44 TB；uint16 放不下 128K 词表）
  Llama-3 405B：15.6T token / 78 天  平均     9 MB/s   （3084 万 GPU 小时 ÷ 16K 张 H100 ≈ 78 天；读数据的带宽只相当于一块硬盘）
  Llama-3 8B：15T token / 15 天（假设）  平均    46 MB/s
  训练时的数据 I/O 微不足道；成本全在训练之前的离线管线里。

=== 配比换算成 epoch：Llama 3 的 15T = 50% 通用 + 25% 数学推理 + 17% 代码 + 8% 多语言 ===
  来源                                目标 token    唯一 token(估)  epoch  Muennighoff 折算
  通用网页（FineWeb 级）                       7.5T            15T    0.5  有效 7.5T（100%）
  数学与推理（网页中筛出 + 论文 + 教材）               3.75T           500B    7.5  有效 3.15T（84%）
  代码（The Stack v2 去重后）                 2.55T           900B    2.8  有效 2.46T（96%）
  多语言                                   1.2T             3T    0.4  有效 1.2T（100%）
  25% 数学推理意味着有限的数学语料要跑多个 epoch，或者靠合成 / 改写扩充；这是 2024 年后合成数据兴起的算术原因。
