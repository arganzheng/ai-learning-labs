== 3. 反向传播：每个参数都拿到一份和自己同形状的梯度
  wte.weight                   参数 (16, 8)      梯度范数 1.0940
  wpe.weight                   参数 (8, 8)       梯度范数 0.6659
  blocks.0.ln_1.weight         参数 (8,)         梯度范数 0.0009
  blocks.0.ln_1.bias           参数 (8,)         梯度范数 0.0012
  blocks.0.attn.c_attn.weight  参数 (24, 8)      梯度范数 0.0493
  blocks.0.attn.c_attn.bias    参数 (24,)        梯度范数 0.0220
  ……共 28 个参数张量、1,952 个数，每个都有 .grad
  为了算这些梯度，前向时每层要存下：LayerNorm 的输入、Q/K/V、attention 权重 [B,h,T,T]、FFN 的 4d 维中间量……
  这就是「激活值」显存：与 B × T 成正比，训练长上下文时它比参数本身还大（第十篇算账）

== 5. 推理：prefill 一次算完 prompt，decode 每步只算一个新 token
  prefill：输入 (1, 3)，每层 cache 里 K 的形状 (1, 2, 3, 4)  [B, h, 已有 token 数, d_h]
  decode 第 1 步：输入形状 (1, 1)，cache 里 K 变成 (1, 2, 4, 4)，新 token 14
  decode 第 2 步：输入形状 (1, 1)，cache 里 K 变成 (1, 2, 5, 4)，新 token 0
  decode 第 3 步：输入形状 (1, 1)，cache 里 K 变成 (1, 2, 6, 4)，新 token 0
  decode 第 4 步：输入形状 (1, 1)，cache 里 K 变成 (1, 2, 7, 4)，新 token 0
  decode 第 5 步：输入形状 (1, 1)，cache 里 K 变成 (1, 2, 8, 4)，新 token 0
  无 cache 生成: [3, 7, 1, 14, 0, 0, 0, 0]
  有 cache 生成: [3, 7, 1, 14, 0, 0, 0, 0]
  两者一致: True

== 6. 计时：T=512、d=64、4 层 4 头，生成 256 个 token（CPU）
  无 cache（每步重算整段，长度 256→512）: 0.73 s
  有 cache（每步只算 1 个 token）       : 0.09 s   快 7.9 倍
  代价：cache 里存着 4 层 × K、V × 512 token × 64 维 × 4 B = 1024 KiB；Llama-3-8B 每个 token 的 KV 是 128 KiB（第六篇）
